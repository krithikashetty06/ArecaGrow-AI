# 🌴 ArecaGrow AI — Arecanut Growth Prediction & Analytics Dashboard

A Streamlit data-science project: data cleaning, EDA, growth and yield prediction (Linear Regression, Random Forest,
Gradient Boosting, XGBoost), explainability (SHAP), statistical analysis (statsmodels) and a plantation health index.

## Data note
The bundled dataset (`data/arecanut_synthetic.csv`) is **synthetic**, generated by
`src/data_generator.py` for development and testing. It is not real farm data, and model
scores on it do not reflect real-world accuracy. To use real data, upload a CSV in the app
(see the template on the Upload page) and retrain.
## Run
```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
First launch generates the synthetic data and trains all models (~1–3 min); artefacts go to `models/` and `reports/`.
Retrain manually: `python -m src.pipeline`.

## Design decisions (good interview talking points)
| Topic | Decision |
|---|---|
| Growth target | Annual **increment** (Δheight, Δgirth, Δleaves), not next absolute value — the latter is trivially predictable from current size and would inflate R². |
| Leakage | Plantation-wise `GroupKFold` and hold-out; temporal hold-out (train early years, test last 2); preprocessing inside `Pipeline`; `nut_count` excluded from yield features; lag features look backwards only. |
| Model selection | Lowest cross-validated RMSE on training plantations; hold-out and temporal scores reported but never used to choose. A mean-prediction baseline is always shown. |
| Missing data | Height/girth/leaf interpolated **within each plantation's time series** (global medians created fake growth jumps — found and fixed during testing); others median/mode. |
| Uncertainty | Empirical 90 % band from out-of-fold residuals — an error band, not a Bayesian interval. |
| Health score | Relative growth-performance index vs age-matched peers (z-scores, clipped). **Not disease diagnosis.** |
| Multi-year projection | Recursive one-year steps with constant conditions; uncertainty grows with horizon. |

## Units
Age yr · pH · soil moisture % vol · temperature °C · humidity % · rainfall mm/month · irrigation per month · fertilizer kg/ha/yr ·
height m · girth cm · leaves per palm · nuts per palm/yr · yield kg dry chali per palm/yr. Palms treated as bearing from age 7 (assumption).

## Structure
```
app.py                    Streamlit dashboard (10 pages)
src/config.py             paths, columns, units, feature lists
src/data_generator.py     SYNTHETIC data generator
src/preprocessing.py      cleaning + outlier handling
src/feature_engineering.py engineered features, leakage-safe targets/lags
src/modeling.py           shared training, CV, selection, persistence
src/train_growth_model.py / train_yield_model.py
src/health.py             health index
src/prediction.py         inference, projection, batch, reports
src/explainability.py     SHAP (+ fallback)
notebooks/                six walkthrough notebooks
models/ reports/ visualizations/   generated artefacts
```

## Limitations
- Synthetic data only until replaced; annual/monthly mean weather, no daily series; no disease labels; no spatial effects.
- Yield uses previous-year yield, so brand-new plantations need an estimate for that field.
- The app UI was written to run with the pinned libraries in `requirements.txt`; the ML pipeline was executed and checked, but the
  Streamlit pages should be click-tested on your machine (see below).

## Suggested next steps
Replace synthetic data; add a location-held-out split; quantile/conformal intervals; hyper-parameter search with nested CV; add pytest tests.
